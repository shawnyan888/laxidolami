# AGENTS.md 学习指南

`AGENTS.md` 是放在代码仓库里、给 AI 编码助手（CodeBuddy、Claude Code、Cursor 等）读的"项目说明书"。助手每次启动会自动读取它，从而了解项目约定——作用类似给新同事的 onboarding 文档，只是读者是 AI。

## 生效机制

| 文件位置 | 作用范围 |
| --- | --- |
| 仓库根目录 `AGENTS.md` | 全仓库生效 |
| 子目录 `AGENTS.md`（如 `packages/web/AGENTS.md`） | 只在处理该目录下的文件时追加生效 |
| `~/.codebuddy/CLAUDE.md` 等用户级配置 | 个人偏好，跨项目生效 |

**就近覆盖**：子目录的规则只补充、细化父目录，冲突时以更靠近文件的为准。

## 写作要点（从示例中体会）

1. **写约定，不写事实**。AI 自己会看 `package.json`、目录结构；文档里该写的是"配置文件里查不到的东西"——为什么这样选型、什么坑要避开。
2. **命令要可直接复制运行**，不要写"运行测试"这种模糊描述。
3. **指令要具体可验证**："错误信息用英文" ✔；"代码要整洁" ✘（AI 默认就会这样做，等于没说）。
4. **正面表述**：说"要做什么"，而不是罗列一堆"不要"。禁令只留给真正的硬红线。
5. **短就是好**。每行都会占用 AI 的注意力，写之前问一句：删掉这行，AI 的行为会变差吗？
6. **分支内容下沉**。只有部分场景才需要的细节（如某个专项的调试方法），放到单独文件里，在 `AGENTS.md` 中用一句话指路。

## 本目录的示例

| 示例 | 场景 | 演示要点 |
| --- | --- | --- |
| `01-minimal/` | 小型脚本项目 | 极简写法，20 行以内 |
| `02-python-backend/` | Python 后端项目 | 完整结构 + 逐段注释讲解为什么这么写 |
| `03-monorepo/` | Monorepo | 分层 `AGENTS.md`，根目录 + 子目录各一份 |

建议阅读顺序：先看 `README`，再看 `01-minimal` 建立骨架概念，然后对照 `02` 的注释理解每一段的取舍，最后看 `03` 理解分层生效规则。
